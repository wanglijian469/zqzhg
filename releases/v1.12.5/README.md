# v1.12.5 · 平台自动处理视频

2026-11-19 网站与 Linux amd64 后端升级。后端及网站代码提交 `10121909d55f0943e1467b3073369c86f3d94cae`，Schema 保持39。Android 保持原签名的1.12.0+53，旧客户端上传同样使用后台转换；本轮未重新制作 APK，未新增安卓真机验收。

厂商上传 MP4／MOV 后，平台自动处理常见不兼容编码，生成可播放的 MP4 及封面。兼容文件直接使用或无损整理；视频时长上限由3分钟调整为5分钟，单文件仍为200 MiB。完整原件私有保留，禁止截断。处理结果仍需厂商保存、提交平台审核，不自动公开。展示版最长边默认1920，不放大小视频；原件保留原分辨率。原件、展示版、封面及审核后公开副本按实际存储计量。

上传页面显示后台处理阶段和进度，“稍后继续”只结束页面等待。后台仍使用原有 MySQL 租约、心跳、超时和单任务锁，无新增中间件或表。配置见 [功能说明](../../docs/VIDEO_AUTO_CONVERSION.md)。

## 升级包及本次操作

`zqzhg-v1.12.5-linux.tar.gz` 是已运行 OSS／Schema39 系统的增量包，内部 `video-auto/patch.json` 列出文件哈希，包含 Go ELF、网站与77项真实行政区边界快照。**不是全新安装包，也不能直接覆盖旧版 v1.12.3。** 不含数据库、企业私有媒体、密钥、登录令牌或 APK。

本次 ECS 操作在开发机加密备份验证后执行：校验包哈希→从当前发布目录建立隔离候选→原子替换新文件，保留下载目录→临时 MySQL 内存管道导入并清空上传／迁移队列，禁止旧对象 GC→以原服务用户启动候选和 Nginx 代理→验证真实 OSS 合成上传、转换、计量和删除→验证生产代理地图、手机和页脚→停止候选→原子切换发布目录并重启服务→正式 HTTPS 复验。

配置 `MAX_VIDEO_SECONDS=300`、`OSS_VIDEO_AUTO_CONVERT_ENABLED=true`。原 OSS 配置、短信、证书、公安备案图标、默认300 MiB及已授权的单企业500 MiB保持。实际厂商原视频已在ECS完成转换，时长197.96秒，原件SHA一致，展示版H.264／AAC、960×544，私有分段读取通过；仅生成私有媒体，没有创建或提交企业视频资料。验收详情见本目录 JSON 回执。

先暂停新增上传／worker并待正在转换的任务结束，再将发布链接、网站和地图路径切回保留的上一兼容 OSS 版本并重启。原 Schema39、业务库、媒体、OSS对象及原件关系保留，不恢复旧数据库、不执行删表或删除媒体。5分钟和单企业额度按用户选择保留。回滚前确认旧程序可以读取已生成的兼容视频及原件引用；不得直接退回不支持OSS的版本。
