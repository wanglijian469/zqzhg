# 厂商密码重置（网站与服务 V1.5.3）

入口为后台“厂商账号”列表，或厂商详情页右侧“厂商账号”。已有公司登录名的厂商显示“重置密码”；没有公司登录名的账号显示说明。本功能不改变账号名称，不新增手机绑定或自助找回。

## 管理员操作

1. 在弹窗核对企业名称与公司登录名。默认随机生成，也可选择“手动设置”。
2. 手动密码输入两次一致，长度为 12–72 个 UTF-8 字节，不能全为空白。中文通常占 3 字节，emoji 通常占 4 字节，空格保留。
3. 点击“确认重置”。处理中不能重复提交或关闭弹窗；取消确认不会修改账号。
4. 成功后复制账号与新密码，交给厂商。密码只显示在此次弹窗，点击“完成”或关闭后清除，不存浏览器本地记录。剪贴板不可用时可手动选择复制。
5. 厂商使用新密码在网站或 App 重新登录，原密码及所有旧会话失效。企业资料、展位、产品、图片、资源及审核记录归属不变。

如果网络超时，界面不会自动重试，也不会声称重置成功。管理员应重新确认后操作；再次成功重置会使前次密码失效。密码不会进入操作日志，也不会进入重置事务的 SQL 错误或慢查询日志。

## 接口与权限

新增 `POST /api/v1/admin/accounts/{id}/password-reset`，请求 `{"mode":"generate"}`，或 `{"mode":"manual","password":"..."}`。成功返回 `account_id`、`login_name`、`password`、`revoked_sessions`，响应使用 `Cache-Control: no-store`。只允许管理员重置有公司登录名的厂商账号；管理员账号、不存在账号及无公司登录名账号均不能重置。

`GET /api/v1/admin/accounts` 支持新增精确筛选 `account_id`，可与已有筛选组合。账号列表和日志接口不返回密码或哈希。

密码哈希更新、撤销全部旧会话及 `account_password_reset` 日志在同一事务内完成。公司密码登录在同一账号行锁下验证并创建会话，重置与登录按序处理，防止旧密码验证的会话在重置后留存。旧会话的后续请求返回 401；已开始执行的请求不由此功能中断。

## 验收及升级

独立 MySQL 库验证：随机／手动重置、权限与不支持账号、UTF-8 边界、原资料与图片归属保留、旧密码及多个客户端会话失效、审核版本不变、日志不泄露密码、日志失败回滚、并发登录／重置。完整后端 25 项顶层测试、Go vet 和网站 25 项测试与生产构建通过。浏览器覆盖两个入口、取消、手动确认、一次性显示、复制失败、手机布局及中英文；业务修改只使用测试账号。
