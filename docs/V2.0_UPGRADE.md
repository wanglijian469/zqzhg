# 中企展馆 ZQZG V2.0 升级与验收

网站与配套后端版本：2.0.0。域名保留 zqzhg.com。主体：河北企元数智科技有限公司。改造基于原项目，不包含生产部署或 Android 改版。

## 项目检查与实现

原项目采用 React 19 / TypeScript / Vite / React Router，后端为 Go / Gin / GORM / MySQL，原服务已有服务端分页、审核公开快照、品牌图片、首页精选与中英文。原 Hall 只有名称及标识，内容无展馆归属；地区为完整名称，型号存在 parameters 文本。

本轮六阶段已落实：

1. 检查公开页、管理页、企业门户、分类与地区接口、迁移及恢复链路，沿用现有业务结构。
2. 展馆配置由 halls 数据驱动；农业机械厅沿用 ID 1 和 agriculture，电线电缆厅 cable 为 preparing；切馆更新 URL、标题和数据范围。
3. 首页改为品牌／搜索、企业品牌展厅、工业产品、免费入驻及页脚。删除产业入口。首屏仅保留后台配置的主视觉照片，不再放置产品小图；中文展馆标题同字号、同一行显示，英文长标题允许自然换行。企业最多8家，产品最多12件，少量卡片左对齐。
4. 找厂家使用紧凑横卡和最多3件产品，缺产品时隐藏右栏；产品卡增加真实型号、分类和厂商链接。厂家20条、产品24条由服务端分页，总数来自后端。支持关键词、分类、地区、排序和 URL 状态恢复。
5. 完成五档响应式、折叠筛选、44px触控、中英文、图片懒加载与失败回退、过期请求取消、页面 Title / description / canonical、ZQZG与版权主体统一。
6. 完成隔离数据库回归、规模测试、生产构建、真实本地浏览器验证与截图；本地服务已更新。

精选与人工排序首先决定入选内容，不足从本厅公开数据补足。入选产品在展示时按厂家和分类轮换，保持同厂入选顺序；不修改后台精选、排序或原始业务资料。SQL使用有限分组候选，兼容本机不支持窗口函数的 MySQL。首页数据不足时少展示。

## 展馆、API 与迁移

新增迁移 server/migrations/011_halls_v2.sql：扩展 halls 的状态、图标、主题和双语描述；contents 增加 hall_id（默认1）及复合索引；为电线电缆厅初始化独立首页设置。支持 DDL 已执行但迁移记录未写入时重试。

- 新增 GET /api/v1/public/halls，返回 items 展馆配置。
- 原 home、taxonomy、vendors、products 接口增加可选 hall=agriculture 或 hall=cable；不传仍为农业机械厅，旧 App 不需升级。
- 原首页、分类和管理接口路径保留；后台首页展示使用 hall 参数选择配置，分类和新建厂商可选择展馆。
- 内容响应增加 hall_id；新厂商可传 hall_id；产品不信任客户端归属，始终继承厂商展馆。分类选择、草稿保存、审核与分类规范禁止跨厅组合。
- 厂家 sort 支持 default / latest / name；产品支持 default / latest。排序使用白名单。产品最新发布采用当前公开审核版本时间。
- 型号沿用原参数文本：卡片识别“型号：”或“Model:”所在行；公开搜索匹配参数文本，不新增必填字段，不搜索私有草稿。
- 列表页仍复用 q、category_id、region_id、vendor_id、page、page_size；浏览器明确传20／24条，后端旧默认及最大100条上限保留。
- 品牌展厅、产品旧链接保持可用；详情以真实内容归属为准，URL中的错误 hall 参数不能改变数据归属。筹建厅不展示公开内容或统计，关闭的展馆详情及图片不公开。
- 数据库名、zqzt.* 本机登录／语言／草稿键、接口路径、备份文件格式及 Android 配置不作品牌替换。备份恢复兼容 schema 10 和11，旧备份隔离恢复后执行新迁移。

未来开放电线电缆厅：先在测试环境维护其分类、企业与产品，配置该厅首页图片和精选；核验资料后将 halls 中 slug=cable 的 status 改为 open。页面与选择器无需改代码。新展馆需新增 halls 行及相同ID的 home_display_settings 行。本轮未建设独立展馆运营后台；仍保持每个厂商账号一个主展厅。

## 本地运行与服务器部署

本地已有依赖时，在项目根目录执行：

~~~powershell
. ./scripts/go-env.ps1
Push-Location web
npm run build
Pop-Location
./scripts/stop.ps1
./scripts/start.ps1
~~~

go-env 同时把 TEMP / TMP 指向项目缓存，避开本机系统临时目录的 esbuild 权限问题。首次安装前端依赖时在 web 执行 npm ci。

网站 http://localhost:8080 ，管理后台 /admin ，厂商后台 /merchant 。后端工作目录必须为 server，读取原 .env；日志为 .local/server.*.log。直接健康检查 /api/v1/health；本机代理环境可用127.0.0.1并禁用代理。

交付目录 delivery/v2.0.0 包含 Windows/Linux 后端、完整 web/dist、配置样例、升级说明、测试报告与 SHA-256 清单。后端迁移嵌入二进制，无需手工执行旧 SQL。部署包不含真实 .env、数据库、私有媒体或签名密钥；现有公开 APK 保持原版本和签名。

服务器部署顺序：

1. 备份数据库、媒体、旧可执行文件、完整网站和运营目录，保留原配置及加密密钥。现有备份、对象存储和恢复配置继续使用。
2. 在隔离数据库验证迁移11，再安排停止旧服务；配套替换后端和完整 web/dist，不混用前后端版本。
3. 保留原工作目录、WEB_DIR、MEDIA_DIR、OPERATIONS_DIR与公网域名配置；后端启动自动迁移。新增展馆不触碰原农业机械厅ID和历史公开地址。
4. 验证健康接口、4家／34件原业务记录、分类地区搜索、分页、登录、图片与电缆筹建页，再恢复对外流量。正式服务器未由本次操作部署。

本机升级前备份：.local/backups/pre-v2-20261017，包含旧程序、旧网站以及 data/database.sql、media.zip 与校验清单。新增迁移不删除旧字段，但其他展馆出现数据后，旧后端会缺少隔离条件；因此不能仅退回旧程序。需要回滚时优先使用兼容隔离的构建，或暂停写入后恢复同一时间点的数据库／媒体／程序／静态资源配套备份。生产回滚与数据切换仍按既有运维流程执行。
