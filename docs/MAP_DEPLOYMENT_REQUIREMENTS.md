# 厂商地图部署一致性要求

要求日期：2026-10-26。用户要求下次部署包中的厂商地图与开发时使用的边界图一致。截图中的省份方块示意图不符合这次要求。

## 当前差异

开发环境通过 `scripts/start.ps1 -MapPreview` 启用真实行政轮廓。前端先读取 `/maps/manifest.json`，没有正式资源时再检查 `/api/v1/dev/map-preview/config`；预览不可用时显示方块示意图。

现有边界预览受开发环境、开关、回环地址和无转发头等条件限制。生产配置和反向代理访问均不能使用该接口，因此把开发启动开关带进部署配置不能解决一致性问题。相关实现位于 `server/map_preview.go`、`web/src/industry-map-preview.ts` 和 `web/src/industry-map-chart.tsx`。

本文记录下一次部署的目标与交付门槛，不代表生产地图现已修复。2026-10-19的本机预览文档继续作为历史实现记录；其中默认生产使用方块图的约定由本次要求更新。

## 下次打包必须完成

1. 以开发使用的边界快照为比对基准，核对全国、省、市、县轮廓、行政编码映射、目录外图形和缺失边界的处理。不得另换简化方块图或改变投影造成形状差异。
2. 为部署环境提供可用的边界资源及生产加载路径，资源随包提供并校验完整性，保持来源与实际用途信息真实。不得伪造授权、审图或资源已核验的记录。
3. 生产页面默认进入边界图模式，复用开发轮廓渲染及统计逻辑。资源失败应明确显示失败并可重试；方块图不能作为成功加载边界的验收结果。
4. 从最终待交付产物启动 `APP_ENV=production`，通过实际反向代理／部署访问路径验收；确认边界加载不依赖本机开发服务、私有缓存或生产环境被禁用的预览接口。使用历史前端归档组包时也必须重新检查，不能直接沿用旧方块图产物。
5. 验证全国→河北→邢台→宁晋、返回上级及历史导航；核对颜色、厂商数、筛选、列表联动、缩放与复位。覆盖桌面和手机布局，并测试边界请求失败后的重试。
6. 在部署说明中记录本次边界快照标识／哈希、资源清单及实际生产配置验收结果。资源缺失或验证未通过时，不能声明地图一致或将该包作为满足本要求的部署包交付。
