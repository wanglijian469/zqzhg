## 已完成的调整

- 保留深蓝侧栏，修复导航文字、图标、悬停、选中状态和品牌区对比度。内容区统一蓝白卡片、表格、输入框、快捷入口及提示样式，成功／警告状态仍保留相应语义颜色。
- 投诉工单、服务协议归入服务管理；删除独立企业身份审核菜单。旧管理地址引导到现有厂商资料审核，原有权限不自动扩大。
- 操作日志使用业务动作名称，注册、密码登录等不再被翻译为服务异常；未知动作显示“其他操作”。
- 网站、App取消独立企业核验表单及提交步骤，不再收集法定代表人、经办人、营业执照和经办授权证明。企业资料不新增统一社会信用代码等强制项。
- 企业资料第三步改为“协议与提交”，原页面内确认当前协议、预览并提交审核。旧核验入口进入该步骤；保留本机／云端草稿、离开提醒、上传重试及待审资料只读状态。
- 企业、产品、视频及画册发布继续经过现有内容审核；未公开企业的产品及资源不会单独公开。修改待审期间继续展示原公开版本。

## 服务端与接口兼容

| 接口或字段 | 当前行为 |
| --- | --- |
| GET /api/v1/public/config | company_verification_mode固定为content_review；capabilities.company_verification为false |
| GET /api/v1/merchant/verification | 兼容返回流程合并标识、协议与确认状态；不返回旧敏感资料 |
| PUT /merchant/verification、POST /merchant/verification/submit | 登录鉴权后返回410 verification_merged，不保存新核验资料 |
| GET /admin/verifications | 按原权限检查，返回合并标识和空列表，不返回历史敏感记录 |
| POST /admin/verifications/:id/review | 按原权限检查后返回410，不再执行独立核验审核 |
| POST /public/service-evidence，purpose=verification | 返回410，不保存新核验附件；投诉附件purpose=request继续使用 |
| POST /merchant/service-acceptances | 复用原协议确认接口，仍要求当前版本和摘要、主动确认 |
| 企业／产品／资源提交 | 取消独立核验前置；仍检查归属、内容规则及所属企业账号的当前协议，管理员代提交不绕过 |

表中相对路径均位于/api/v1下。旧客户端保留浏览、登录及草稿能力；使用旧核验写接口会得到升级或使用网站的明确提示。

历史核验表、附件、审核快照、账号、企业资料、媒体引用和网址保留。旧附件继续使用原私有读取权限，不迁入公开媒体、不增加人员权限，不自动删除。常规界面不再显示或要求补交这些历史材料。

## 回退与主要改动

界面或运行问题优先通过保留资料审核模式的新修复版本处理，在候选实例验证后切换。不得直接恢复旧程序重新强制采集四项材料；不得用旧SQL覆盖升级后新账号、新资料或新协议记录。恢复服务文案应发布新的修订版本，保留既有版本及确认记录。

Android回退界面应使用versionCode高于42的修复包，保留固定地址和精简审核规则；不建议卸载回退，以免丢失本机未上传草稿。

主要改动集中在服务端content_review及服务协议／核验兼容接口、迁移026／027；网页后台样式、业务日志、协议确认与企业编辑器；Flutter协议组件及旧入口兼容。内部运维脚本为deploy/linux/content-review-release.py；打包和验收脚本位于scripts/目录。
