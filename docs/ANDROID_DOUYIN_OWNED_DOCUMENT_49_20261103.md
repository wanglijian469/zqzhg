# 49版：修复官方播放器自有页面的拦截回归

## 用户反馈与证据

用户确认第一版添加抖音链接时可播放；之后多个候选在小米MIX4上均失败，原视频在抖音中正常。48版截图显示：Android12、WebView156.0.8078.47、原因http、编号403，服务主机名为空。因此不能直接把此403归因于抖音服务器，也不能继续笼统建议更换视频。

源码对照：首次实现 `c703493` 的 `VideoPlayerActivity` 使用 `loadDataWithBaseURL`，没有资源拦截回调。后续 `08dfcf3` 抽取 `OfficialVideoView` 时新增远端资源过滤；只有HTTPS官方资源可通过，应用自己的本地HTML加载没有单独路由。47/48版对此拒绝返回403。Android文档说明 `shouldInterceptRequest` 也可能接收data等非网络请求，不能假定该回调只包含远端视频资源。

**已确认自有页面与远端过滤混用的代码缺陷，截图与该路径一致；48诊断没有记录scheme和frame标志，未捕获MIX4上具体被拒URL。49版仍需手机实播确认，不能把推断写成已完成真机根因复现。**

## 针对性改动

- 新增纯Java `OfficialVideoDocument`，由经过验证的官方播放器地址、比例和应用生成的随机标识生成固定HTML。
- 使用单实例、单会话、精确HTTPS自有路径。WebView通过普通 `loadUrl` 加载，只有完全匹配的主文档由应用本地返回200、UTF-8 HTML和no-store；不会请求ECS该路径，不把整个zqzhg.com加入远端白名单。
- 抖音iframe及资源继续使用原HTTPS与域名规则。其他主页面、其他会话地址、任意data/file/content/javascript、伪造主机和其他平台地址不被放行。没有撤销资源校验、证书校验或沙箱，也没有执行用户HTML。
- 将应用自身策略返回的403明确标记为 `app_policy`，与远端HTTP错误区分；诊断增加协议类型和主文档／资源范围，只保留这些类别和主机名，不保留原始data内容、路径、查询、媒体签名和令牌。
- 保留48版慢加载等待、停止隔离、手动重试、全屏返回和原视频入口。产品、企业管理、审核、协议、配额及网站业务保持。

本轮不是恢复第一版全部实现或删除安全规则，仅修正自有文档的加载入口。原iframe样式与官方控件继续使用。

## 实际验证

- 80项Java策略与会话回归通过，包含“旧HTTPS远端规则会拒绝自有文档，新路由对本会话主文档返回DOCUMENT”的回归；其他会话、子frame借用、修改查询或片段、伪造地址、任意data及危险协议仍拒绝。
- 使用生产同一个Java文档生成器及请求路由进行Chrome触控测试，没有另写HTML或复制域名表。自有文档200、本地返回、对ECS自有路径出站请求数0；用户触控后视频播放时间推进约3.37秒，非暂停、媒体错误0、未静音。此结果是浏览器对照，不是Android实播验收。
- 4个相关Flutter文件19项通过，回归输入、重复粘贴、窗口单实例、关闭、返回、后台停止及授权兼容。
- 原正式签名Release构建、真实版本1.10.9+49、非调试构建、237项资源哈希及新路由代码进入DEX校验通过；地图最终产物检查见回执。
- 当前没有已完成的49版MIX4实播、原生全屏／后台验收。本轮没有更新正式下载，也没有修改ECS程序、数据库或站点配置。

官方参考：[应用内本地内容加载](https://developer.android.com/develop/ui/views/layout/webapps/load-local-content)、[WebViewClient资源拦截](https://developer.android.com/reference/android/webkit/WebViewClient)。
