# 网站图片与访问轻量化

实现及性能测试日期：2026-10-26。网站前后端已实现多尺寸图片、按需加载、图片重新验证缓存及静态资源gzip；未修改原生安卓，未部署远程环境。2026-10-28已恢复本地8080服务，开发边界图预览保持开启。

## 展示与兼容

- 媒体接口及 `/media/:id` 别名支持 `w=240|480|960|1440`，按最长边缩小，不放大小图、不裁剪；含透明通道保留PNG，其余预览使用质量80的JPEG。
- 旧的 `thumb=1`、原有高清查看和下载保持兼容；`w` 与 `thumb` 不混用。新展示图复用已通过权限、公开状态及水印检查的源对象，不覆盖原图；历史图片自动按需生成。
- Logo和缩略图、列表、主图分别使用相应尺寸候选。首屏主图优先，其他图片在进入视口附近时开始加载；私有图片同样延迟请求。手机与桌面产品图库只挂载当前布局，点开再请求现有高清图。
- 服务端SEO正文图片也采用懒加载预览，分享和结构化元数据保持高清地址。加载区预留尺寸，防止图片及页脚跳动。

## 缓存和部署

默认派生缓存位于现有运维目录的 `image-cache/`，与公开网站和业务媒体目录分离。可通过 `IMAGE_CACHE_DIR` 指定独立私有目录，通过 `IMAGE_CACHE_MIB` 调整容量，默认512 MiB。缓存键包含源哈希、尺寸及编码版本；读取校验内容哈希，损坏重建。最多2个编码任务，同一派生请求合并。访问时清理闲置超过7天的文件，写入时按容量淘汰；失败回退现有授权缩略图／展示图。

公开图片使用 `private, no-cache` 与ETag，每次重新检查是否公开、是否可读，检查成功且内容未变才返回304。私有图片、下载、业务接口和错误响应仍禁止缓存。无需把OSS对象设为公开，也无需CDN、数据库迁移或新增编码器。

Vite生产构建自动为较大的JS、CSS和SVG生成 `.gz` 文件；Go静态服务按 `Accept-Encoding` 返回压缩内容，保留 `Vary`，范围请求使用未压缩文件。带哈希的JS／CSS使用一年缓存和 `immutable`；HTML及运行配置保持及时更新。部署时必须同步新的后端与整套前端产物，包括 `.gz` 文件；反向代理不得替换媒体的权限和缓存规则。

缓存可以删除重建，不纳入原图或业务备份；回滚旧程序和前端无需回滚数据库。下一次部署包仍须满足 [地图部署一致性要求](MAP_DEPLOYMENT_REQUIREMENTS.md)，本次本地开发预览不代表生产地图已通过交付验收。

## 验证与复现

原始性能结果与汇总见 [验收数据](test-output/image-loading-20261026.json)。基线由改动前源码及生产构建独立运行；使用一次性测试库、确定性的2048×1280纹理图片、透明Logo、12家测试厂商与24款测试产品，没有向业务库插入测试内容。每版40组浏览器采样：五类页面在390／768／1440视口运行，并在1.6 Mbps、150 ms延迟下逐页运行5次冷缓存采样。

执行 `node scripts/summarize-image-performance.mjs` 可从 `.local/lightweight/` 中的两版浏览器结果重新计算汇总，并校验当前 `web/dist` 所有gzip产物。图片传输量统计包含响应头；304仍有少量头部传输，图片正文不再重复下载。这里的数据是隔离场景结果，不能替代线上用户监测。
