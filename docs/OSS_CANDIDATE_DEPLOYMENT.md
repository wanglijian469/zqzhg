# OSS 039 候选部署与回滚

**当前是真实 OSS 合成验收通过的候选，不是已验收的生产升级包。** 独立备份操作凭据、ECS 正式路径及 Android 真机验收仍未完成；不得直接解压覆盖正式站点。完整功能、API、环境变量见 [OSS_STORAGE.md](OSS_STORAGE.md)，实际验证范围见 [OSS_TEST_RESULTS.md](OSS_TEST_RESULTS.md)。

11 月 19 日更新：分片权限、真实私有上传／校验／额度、平台与企业公开读取及非公开目录限制均已通过，详见 [真实验证记录](OSS_ACCEPTANCE_20261119.md)。用户本轮明确不迁移、不删除现有生产文件；原第 6 步及历史清理操作暂不执行，仅验收合成对象。完整合成测试在临时 MySQL 实例运行，没有启用正式站点 OSS 或修改正式配额。

## 候选内容与检查

`manifest.json` 标记源码基线及每个变更文件哈希、Linux 二进制哈希、77 个开发地图快照、Android 候选和未完成验收项；`SHA256SUMS` 覆盖候选目录。打包脚本会重新读取归档逐文件验哈希。归档不包含真实环境变量、数据库、企业原件、密钥、签名证书私钥或正式下载包。

没有自动升级脚本：当前 ECS 系统盘已约 96%，旧升级流程会制作本地全量备份，不适合本次改造。之前批准删除的 17 个临时目录已处理，不能将该授权扩大至其他历史发布或备份。

## 激活前顺序

1. 管理员按 `deploy/oss` 配置北京区两个业务 Bucket 和独立备份 Bucket；网站角色保留原短信权限，不增加备份权限。私有 CNAME `upload.zqzhg.com` 和公开 `img.zqzhg.com` 均应具备有效 HTTPS；核对 CORS 精确来源、公开前缀策略及阻止公共访问的实际影响。任何策略变更应按管理员确认范围执行。
2. 检查磁盘可用空间、配额、`ffmpeg`／`ffprobe`／libwebp／Poppler、MySQL 工具及原环境配置保全。新程序、前端和地图先放独立候选目录；不要替换 `/opt/zqzt/current`，不要接正式 worker。
3. 停止网站及在途写入，等待短时上传授权过期和校验排空。使用独立 STS 与离线保存的加密密钥，经 stdin 执行 `oss-media backup` 并 `verify-backup`，SQL 加密流直传备份 Bucket，不在 ECS 生成全量 ZIP。schema 038 可由该独立命令先备份。不能使用网站角色代替操作凭据。
4. 在隔离库、独立 worker／运维目录中启动候选；先验证 039 升级、当前厂商额度与历史覆盖值、读取原媒体、短信登录、手工资料编辑及平台审核。启动新程序会安装迁移，应先确认它指向隔离库。地图使用随包 `map-demo`，`MAP_DEMO_ENABLED=true`、`MAP_DEMO_DIR` 指向该目录；不能依赖开发预览接口。
5. 管理员明确触发 OSS 合成对象检查；验证私有匿名拒绝、签名 PUT、GET Range、分片、CORS、删除和指定公开前缀。通过前保持 `OSS_ENABLED=false`。验证阶段仅在候选进程启用功能，不将未验证配置写入正式服务。
6. 对洋柯 67、派一 79 先 dry-run、核对差异和配额，再明确迁移；两份未知本地文件先人工核对，不自动关联。迁移保留原文件作为恢复副本，不安排自动清理。
7. 从待切换 Linux 产物、实际生产反向代理路径复验全国→河北→邢台→宁晋、统计、手机布局及失败重试。APK 需独立真机验证；Android 构建不等于已批准替换正式下载。
8. 通过上述检查后，保留当前生产环境文件和其他站点配置，按现有 systemd／Nginx 路径执行候选切换。迁移及配额更新先确认备份和停止写入。`web/dist/downloads` 必须继续使用已核验的现有正式下载目录；本候选不带下载目录，不能因此让原下载入口 404，也不能把候选 APK 自动改为正式版。

具体数据库、实际 MediaRoot 和发布路径读取现有 active target；不把开发样例路径写入生产。启用后先复核私有访问、公开访问、厂商越权、额度、任务队列、日志脱敏和其他站点健康，再扩大迁移范围。

## 故障处理与回滚

- 先 `OSS_UPLOADS_ENABLED=false` 关闭新会话，保留既有媒体读取和在途确认；等待处理结束后停止 worker，维护锁保护数据库一致性。
- 已存在 OSS-only 文件时，程序必须回到支持 schema 039／RemoteKey 的 OSS 基础版本。保留批次、草稿、对象映射和表，不能直接回退 v1.12.3。当前候选可作为后续经验收的 OSS 回滚基线；在通过实际部署检查前不能称其为已验收基线。
- 因公开副本失败而未切换的业务继续保留旧公开版本，修复后重试对应任务；不能直接改数据库为公开绕过复制校验。
- `rollback-oss-039.sql` 只在导出、核对且没有云对象或活动预占／会话／保护后单独执行；先设置 `@oss_metadata_export_verified=1`。禁止 mysql `--force` 忽略 guard 继续执行。正常程序回滚不运行删表脚本，不回改厂商自定义额度或删除历史协议。
- 独立恢复仅导入随机隔离库和新对象键。核对备份 manifest、媒体和权限后，正式 active target 切换需要另行明确批准；恢复命令本身不会切换。
