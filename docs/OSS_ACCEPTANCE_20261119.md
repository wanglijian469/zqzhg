# OSS 真实云端验证记录（2026-11-19）

本文为正式上线前的合成验收历史记录。用户随后授权两家企业迁移及开发机备份，已完成正式上线，当前结果以 [v1.12.4 上线记录](RELEASE_1.12.4_20261119.md) 和发布回执为准。

本轮遵守“不迁移、不删除 ECS 现有生产文件”。正式站点未切换，生产数据库、角色授权和 Bucket 策略均未由程序修改。云配置由管理员操作。

**最终结论：补齐企业公开目录策略后，更新后的完整合成云端验收通过，退出码为 0，`passed=true`、`synthetic_cleanup_completed=true`。平台与企业公开前缀匿名读取均为 200，公开 Bucket 的临时目录匿名读取为预期的 403。** 这代表真实 OSS 合成流程通过，不代表已完成正式站点切换、真机或独立备份验收。

## 已解决的公开目录授权问题

管理员补齐公开 CORS、私有响应暴露头后，分别读取到精确 `https://zqzhg.com` 来源及 ETag、Content-Length、Content-Range、Accept-Ranges。

最初独立合成对象诊断曾返回以下错误；这是历史失败记录，管理员修正公开前缀策略后已解决：

| 字段 | 实际值 |
|---|---|
| API | GetObject |
| HTTP／OSS 错误 | 403／AccessDenied |
| EC | 0003-00000001 |
| 身份 | 匿名读取；写入为 ECS 实例角色 ZQZHG-SMS-Role，写入成功 |
| 资源 | `acs:oss:*:*:zqzhg-public-media/platform/published/preflight/340dc4ff7db696057bb321abd43f05e2.txt` |
| Request ID | `6AFE43CDB3C065303285BB1F` |
| 服务端信息 | You have no right to access this object because of bucket acl. |

平台目录修正后，补做真实业务形状的 `companies/1/published/<随机文件名>` 检查，曾得到相同 EC，Request ID 为 `6AFE63322FFD4536392FE0BD`。管理员随后补齐企业公开目录策略，再次实测已返回 200；非公开临时目录仍为 403。诊断均使用本轮合成对象，已全部删除并确认。

最终完整验收采用补强后的检查程序重新运行，验证平台、企业及非公开目录三种范围后才标记通过。候选包同时保存完整验收、独立目录边界检查和清理结果，任何一项缺失均不标记真实云端完整通过。公开权限继续按 [前缀策略](../deploy/oss/public-prefix-policy.json) 限制；不扩大为整桶公开，不自动修改账号级公共访问保护。

## 本轮代码补强与回归

- 管理员连通性检查增加 Range 所需的 CORS 暴露头验证，缺项时给出具体提示。
- 公开检查覆盖平台与企业实际发布路径，同时验证临时路径匿名拒绝；修复只测平台目录就错误显示公开能力已就绪的问题。增加“企业目录策略缺失”和“误开放整桶”两类回归验证。
- 单文件、读取和分片统一采用 `OSS_UPLOAD_TIMEOUT`，默认 300 秒，限定 30～900 秒；修复分片原来固定 300 秒而忽略配置的问题。
- 只读权限预检增加 API、资源、错误码、HTTP 状态、EC、Request ID、角色和检查时间；不输出签名 URL、密钥、Token 或原始 SDK 错误。
- 新增显式开关保护的真实云端合成验收测试；默认单元测试跳过。仅独立实例运行，按本次测试库清单清理对象，不枚举删除生产 Bucket。
