# 农业机械馆分类升级（Schema17）

> 本文为Schema17历史交付记录。当前精简目录、检索与地图说明见 [Schema18更新](TAXONOMY_COMPACT.md)。

本次同步升级响应式网页、运营后台和Flutter App。网站与后端沿用2.0.0版本标识；Android升级包为 **1.8.0-rc.2+31**，包名和签名不变。生产未部署，既有正式下载包不替换。

## 使用入口

- 找厂家：独立厂家分类、所在地区、产业带和经营性质筛选；主营和兼营均可匹配，同一家企业只计一次。
- 企业资料：基础资料内选择1个主营及最多2个兼营，三者不能重复。经营性质选填，产业带由后台关联。
- 产品发布：保留三步流程；搜索分类名称、别名或完整路径，也可根据名称和关键词获取最多3项推荐。推荐须点击应用。
- 产品品牌、型号、适用品牌和适用机型均选填。适用品牌及机型支持逗号分隔的多项输入，最多30项。原参数文本不重写。
- 后台 `/admin/categories`：厂家分类、产品分类、历史映射三个标签；页面下方展开产业带管理，搜索并关联厂家。

新厂家和新产品提交审核时必须具备相应分类，保存草稿可空。历史资料可保留原分类；主动重新分类后采用新规则。停用分类退出新选择和推荐，既有公开内容保留，原已发布分类可随资料继续编辑。

## 初始目录与维护规则

厂家初始14类，顺序为：农机整机、耕整地机械、播种施肥机械、收获机械、田间管理与植保、农机具及配套设备、农机零部件、动力与传动、液压与底盘、电气与智能控制、灌溉与设施农业、畜牧与饲料机械、农产品加工机械、机械加工与定制。

产品初始20个一级分类：拖拉机与动力整机、耕整地机械、播种施肥机械、田间管理与植保机械、收获机械、收获后处理与搬运设备、畜牧养殖与饲料机械、农产品加工机械、农机具及配套设备、农机易损件、传动系统及零部件、发动机及配件、液压系统及零部件、行走底盘与转向制动、收获机械专用件、耕作播种专用件、轴承密封与标准件、电气与智能农业设备、灌溉排水设备、设施农业设备及配件。

完整中英文二级目录与稳定编码见 `agriculture-taxonomy-schema17.json`，源目录定义在后端 `taxonomy_catalog.go`。厂家为一级目录，产品最多三级；新增产品选择末级。管理员细化三级时，原来已选二级分类的内容保留原关联，新选择使用末级。

刀片、犁铧、摩擦片等归易损件；收获、耕作播种专用件收录作业机构和结构件。传动、发动机和液压部件按系统归类，适用场景通过品牌、机型表达。

后台可维护名称、英文名称、排序、搜索别名、图片及启停状态。图片可空，使用原图片上传和存储体系。合并限同展馆、同用途，保留来源和别名；有引用或子分类时不能删除。删除采用逻辑删除并记录日志。

## 数据、兼容和迁移

- 新增 `017_agriculture_taxonomy.sql`。现有分类增加用途、稳定编码、图片及别名；新增版本分类关联、历史映射、产业带和厂家产业带关联表。
- 原分类ID、原始内容、审核快照及媒体归属保留。原始 `category_id` 继续存在；新增 `primary_category_id`、`secondary_category_ids`、`product_category_id` 等字段。
- 分类关联随版本保存，公开查询只读取当前公开版本。新草稿或待审版本不改变公开分类及统计。
- 旧客户端没有发送的新字段由服务端保留；显式零值、空字符串、空数组才清空相应字段。产业带不接受厂商表单赋值。
- 仅明确一对一的旧分类自动匹配，例如产品液压油缸；宽泛分类、空分类和多义分类进入人工列表。人工处理支持预览、逐条或最多100条批量确认，原始快照不改写。
- DDL可重复执行，数据按版本幂等补充；迁移版本标记最后写入。迁移中断后重新启动继续执行。
- 备份恢复接受Schema17，并包含新增分类关联、映射和产业带。验收覆盖真实加密备份、隔离恢复和切换回退。

taxonomy接口新增 `category_kind=vendor/product/legacy/all`，省略时仍返回旧共享目录。`all`用于读取历史显示名称；停用项不能新选。新增推荐、合并、删除、历史映射及产业带接口，见 `openapi.json`。运营操作沿用 `taxonomy.manage` 权限和操作日志。

## 部署与回退

1. 保留当前数据库、媒体、运行环境、控制目录和程序的完整配套备份。
2. 解压服务端升级包；已使用托管Linux部署的，可先运行 `sudo bash upgrade.sh --check`。该步骤只检查，不修改服务。
3. 正式升级运行同包 `sudo bash upgrade.sh --apply`，按原环境替换配套程序和网页。迁移由新后端启动执行，不能只更新网页或只执行部分SQL。
4. 检查健康接口、登录、14/20初始目录、产品发布、审核、产业带筛选及历史映射数量，人工处理未匹配记录。
5. Android预发布包与Schema17后端配套使用；正式下载入口保留原包，安装新包前先完成后端升级。

回退网页或App时继续使用能保留新字段的兼容后端。不要删除新增列、关联表或迁移数据，不要将Schema17备份交给旧版恢复器。若必须回退整套程序，先保存升级后的新增业务数据，再按配套备份执行受控恢复，避免覆盖升级后的录入。
