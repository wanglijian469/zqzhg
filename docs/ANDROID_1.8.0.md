## 技术实现与变更文件

- `mobile/lib/procurement_workspace.dart`：入口、服务能力检查、产品上下文、业务会话与语言同步；返回的新会话必须通过当前服务器 `/auth/me` 校验后才接收。
- `mobile/lib/main.dart`、`app_navigation.dart`、`merchant_workspace.dart`：原生入口；`native_auth_entry.dart`：独立短信登录；`product_quality.dart`：原生产品填写提示。
- `mobile/android/app/src/main/kotlin/com/zqzt/dalunongji/WorkspaceActivity.kt`：私有工作台 Activity，加载 APK 内置页面；同源 API 请求正常访问配置的服务器，未放宽后端 CORS 或权限。关闭文件 URL 访问、WebView 调试及私有页缓存，不使用 `addJavascriptInterface`，会话不放入 URL；私有页禁止系统截图及最近任务预览。
- `mobile/android/app/src/main/assets/native-workspace.js`：一次性会话初始化、退出后重载保护、私有 Blob 附件预览与保存；限制 20 MB，不把令牌写入下载地址。
- `MainActivity.kt`、`AndroidManifest.xml`：内部 Activity 通道及系统文件选择/保存；保留原分享能力。
- `scripts/prepare-android-workspace.ps1`：类型检查、Vite 构建及明确资源清单；不把网站下载 APK、配置文件、数据库或密钥装入内置资源。
- `scripts/build-apk.ps1`：独立 `-BuildOnly` 模式，校验原签名、包名、版本和构建时源码一致性，避免交付过期 APK。若本机 Flutter 的 Gradle 包含构建失败，则停止旧 daemon，使用新进程重试；只有最终构建、签名和版本校验全部成功才产出交付文件。
- `mobile/test/procurement_workspace_test.dart`、`scripts/android-workspace.test.cjs`：新增入口、会话同步、路径约束、短信登录和附件桥接测试。

Web 资源按路由加载，采购和后台代码不会因本次封装重新并入公共首页入口。构建生成的资源在 `mobile/android/app/src/main/assets/workspace/`，由脚本生成并忽略入库，包含逐文件 SHA-256 清单。

## 默认服务器现状和部署前置条件

本轮仅对默认服务器进行了健康检查和公开配置读取，没有部署或写入生产数据。健康接口正常，但其公开配置尚未返回 `capabilities.procurement=true`，属于旧版服务。**APK 已包含采购页面；旧后端需要配套升级后才能使用采购功能。** 入口会给出明确更新提示，原有接口继续保留。

发布负责人应先按项目现有部署及迁移方案备份数据库、对象和运行配置，在隔离环境验证网站与 Go 后端、Schema21 及私有附件存储，再更新服务端和网站。不要通过伪造能力标识、跳过认证或在真实业务库灌入演示数据启用功能。确认采购 API 和文件权限正常后，发布此 APK。本轮不替换网站下载、不部署生产、不发送真实短信。

短信服务仍由服务器控制：正式环境使用既有阿里云配置和验证码模板；只有明确的开发短信环境才显示动态模拟验证码。APK 未内置固定验证码、阿里云密钥或演示登录会话。默认地址按用户要求保留 HTTP；未来切换正式 HTTPS 地址时应同步调整服务器公开地址与应用设置。

## 验证结果

最终测试数字及包校验以交付目录 `verification.json` 为准。测试原始摘要放在交付包 `checks/`，不包含登录凭据。

- JavaScript 桥接测试 4 项通过，包含退出后重载、私有下载、大小限制和预览意图。
- 内置 Web 构建的 TypeScript 类型检查和 Vite 构建通过。
- 用本次 Web 构建资源运行采购 Playwright 回归：**89 组布局检查，0 页面脚本异常**。覆盖 1920×1080、1366×768、390×844 及中英文；询价、私有附件、两家独立报价、比价、意向电话授权、审核扩散、洽谈与结束均通过。夹具只写入随机命名的隔离测试数据库，结束后清理，不修改主站资料。
- Playwright 验证的是内置页面资源与同版本后端契约，不能代替 Android 系统 WebView 或真实手机测试。
- Release 构建、Android v2 签名、包名、版本、ABI 及内置资源清单完成校验；最低 SDK 24、目标 SDK 36，包含 arm64-v8a、armeabi-v7a、x86_64；沿用原发布证书，可覆盖原同签名低版本安装。

7 个 Flutter 用例因明确环境开关跳过：6 个历史截图生成用例、1 个要求专门后端地址的移动端集成用例，未记为通过。采购浏览器回归另外使用隔离数据库执行。

**未验证项**：本机没有连接 Android 设备或可用模拟器，尚未执行真机安装/升级、启动、相机、系统文件选择和保存、PDF 分页、物理返回键、系统杀进程恢复及不同系统 WebView 兼容性。发布前须至少在一台真实 Android 设备上验证；无法将编译成功视为这些能力已实测通过。生产阿里云短信、OSS、ECS 及旧服务器升级也未执行。

## 安装与验收

1. 将交付 APK 下载到 Android 手机，按系统提示允许此次安装。原同包名同签名低版本可以直接覆盖升级，避免先卸载丢失本地数据。包内附 SHA-256 和发布证书指纹供核对。
2. 验证桌面名称为“大陆农机”，原厂商/产品浏览、收藏、账号、设置、展厅与产品管理正常。
3. 当前默认旧服务器显示采购升级提示属于预期；切换到已升级且手机可访问的测试服务器后，验证采购与厂商入口、登录续办、报价、比价和会话。手机上的 `localhost` 指手机自身，不能用电脑的 localhost 地址代替局域网服务地址。
4. 在隔离演示服务中可使用既有演示手机号 `13900009001`（采购）、`13900009002`（厂商甲）、`13900009003`（厂商乙），点击获取动态验证码登录。账号只在演示库有效，不应假定默认生产服务器存在这些账号；不向真实手机发送测试短信。
5. 真机验证照片选择、PDF/图片预览、Office 下载、返回和未保存离开提醒。未获得授权前不在真实业务库发布测试需求、报价或审核。

Android 版本号已从稳定版 `1.7.0+29` 提升为 `1.8.0+35`。旧包不能通过普通覆盖安装降级回 29；如需回滚，优先修复后使用更高 versionCode 发布，保留本地草稿及收藏；卸载重装前须先确认数据保存与用户授权。原网站稳定下载文件保留，回滚服务端按现有备份方案独立执行。
