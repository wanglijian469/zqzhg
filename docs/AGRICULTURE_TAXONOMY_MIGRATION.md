# Schema17 本地迁移验收报告

> 本文为Schema17历史交付记录。当前精简目录、检索与地图说明见 [Schema18更新](TAXONOMY_COMPACT.md)。

验收日期：2026-10-20。环境：Windows、隔离 MySQL 测试库；不是生产迁移报告。生产厂家、产品和待处理记录的实际数量须在部署后核对。

## 目录清单

`agriculture-taxonomy-schema17.json` 包含 14 个厂家分类、20 个产品一级分类及 114 个正式二级分类，共 148 项，均有中英文名称和稳定编码。分类图片初始为空。三级由管理员按业务需要维护。

## 自动映射规则

映射按内容版本与厂家／产品用途分别建立，不能用产品映射替代厂家的主营判断。

| 来源 | 处理 |
|---|---|
| 旧分类名称与对应用途的新目录名称完全相同，且唯一 | 映射到该分类；产品须为末级 |
| 产品“翻转犁” | 铧式犁（`agri.product.02.01`） |
| 产品“驱动耙” | 耙地机械（`agri.product.02.05`） |
| 产品“齿轮” | 齿轮与齿轮轴（`agri.product.11.01`） |
| 农业机械、农机配件、分类为空、无唯一匹配、产品目标非末级 | 待人工处理，继续展示原分类 |

映射独立于原始 `category_id`、审核快照和媒体关联；不更新这些历史原文。管理员在“分类管理 → 历史映射”中搜索资料，查看旧分类、原版本及候选目录，选择目标后先预览，再确认。人工操作保存到版本分类关联与映射表，并记录日志。

## 隔离样本结果

`TestTaxonomyHistoricalBackfillAndMerge` 构造 3 个已审核产品版本：旧分类分别为“液压油缸”、“农机配件”和空值。

| 检查 | 结果 |
|---|---|
| 初次初始化 | 1 条精确自动映射，2 条待人工处理 |
| 再次初始化 | 数量不增加，无重复关联 |
| 人工预览 | 仍为 2 条待处理，不写入变更 |
| 批量确认 | 2 条变为人工映射，原始版本 JSON 不变 |
| 模拟 DDL 完成但迁移标记未提交，再次启动迁移 | 成功，原始版本 JSON 不变 |
| 合并新分类 | 查询解析到目标，来源分类及历史分类保留 |
| 真实浏览器人工映射 | 预览、确认后列表更新，原始快照不变 |
| 加密备份、隔离恢复和切换 | 新分类关联、人工映射与产业带关联恢复一致 |

完整业务测试另外覆盖：主兼营去重及数量、二三级和循环限制、跨用途拒绝、品牌机型搜索、停用与图片访问、新旧客户端、未审核草稿不改变公开分类、产业带筛选和权限隔离。

生产升级前须使用实际业务备份，并记录原分类数量、厂家产品数量、公开与待审版本数量及媒体引用。启动新后端后复核上述数量，在后台记录自动映射及待处理数量。不能将本报告的隔离样本数量当作生产迁移数量。

## 可复现检查

在已配置隔离测试 MySQL 的工作区运行：

```powershell
cd server
. ../scripts/go-env.ps1
$env:RUN_MYSQL_TESTS='1'
go test -count=1 -skip '^TestVideoWorkerProcessingRetryAndRecovery$' -v ./...
go test -count=1 -run '^TestVideoWorkerProcessingRetryAndRecovery$' -v .
go vet ./...
```

真实浏览器检查另需 Edge、`scripts/verify-taxonomy.cjs` 所需的 Playwright 依赖和已构建的 `.local/taxonomy-dist`；设置 `$env:TAXONOMY_BROWSER_HARNESS='1'` 后运行 `go test -count=1 -run '^TestTaxonomyBrowserHarness$' -v .`。不使用生产数据库执行这些测试。

部署、保留新增数据的兼容回退及未验证项见 `AGRICULTURE_TAXONOMY.md`；接口见 `openapi.json`。所有交付包均附 SHA256 清单。
