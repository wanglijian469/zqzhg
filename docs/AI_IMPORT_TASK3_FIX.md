# 劳斯耐斯画册：任务3刷新与识别修复

2026-11-17，本机 `http://127.0.0.1:8094/merchant/ai-import/3`。仅修复开发候选，未部署生产、未提交或批准企业／产品业务版本。

## 实际原因

- 页面每2.5秒调用共享 `useLoad.reload`，其请求版本变化时会暂时隐藏旧响应。任务页随之显示“加载”，卸载并重建企业和产品编辑器，引起整页闪动、反复请求分类及图片。
- 后端原先按整项产品增加百分比。一项跨6页产品需要6次提取、1次合并和6次复核，在该产品保存前进度均停在35%，难以分辨正常等待与停滞。
- 本次目录按相同标题／型号把多页独立展示合成4组，其中一组覆盖物理第2、3、8、9、10、11页，不能可靠保留结构和配置差异。
- 原运行在最后一组产品提取时得到合法JSON `{}`，旧结构转换把它当作空对象通过，随后因缺来源页报 `ai_invalid_source_page`，任务最终在76%失败。

## 修复

1. AI任务使用独立的后台刷新hook：同路径、同会话的请求保留当前结果，稳定的reload函数不会卸载编辑器；刷新失败保留页面并显示重试提示；切换任务或会话不展示旧数据。
2. 按实际完成的逐页提取、跨页整理、复核和草稿保存单元更新进度。任务返回 `work`，含当前产品序号／总量、来源页、步骤完成数、当前步骤开始时间及说明。页面明确提示处理中展示的是阶段性结果，不以计时器伪造百分比。
3. 目录增加程序约束：独立product区块不得因标题或型号相同而消失；缺漏区块补回，单一产品同页的支持区块关联保留；多页纯支持内容可以沿用明确关联。来源页排序稳定，是否确实为重复产品留待厂商人工合并。
4. 空产品响应、错误根层级、空页目录／企业来源等作为结构错误进入已有单次、有审计的修复调用。已保存但不符合当前结构的缓存不会反复重放；成功修复结果复用检查点，不重复计费。
5. 逐页提取先检查来源及图片区域，发现整页照片建议时自动重新提取一次；仍无法可靠裁剪的图片拒绝使用、明确标记需人工框选，保留参数及其他安全图片，并继续后续产品。该分支用两次持续返回整页照片的模拟响应验证，不能以整页照片充当成功主图。
6. 标题明确列出的型号即使在参数表中没有数值，也要求保留空参数型号，不从其他型号补值。卡片展示实际参数记录／来源和缺参数型号数，避免用“100%”误表示全部画册内容已覆盖。
7. 当前任务重新解析前核实旧产品草稿全部为自动生成版本1、未确认、未提交。3项旧草稿软归档并保留数据及来源，记录操作日志；原任务ID／文件／历史调用保留，未动用户已有企业和公开产品。已提交、已确认或人工编辑过的草稿不允许该自动重置。

新的结构保留规则识别到10个独立展示区块。这是根据本次实际目录产生的结果，不是预设产品数量。原画册共12个物理页，第1页封面、第12页联系方式；同型号照片、结构和配置是否属于同款，仍应由厂商审核。
