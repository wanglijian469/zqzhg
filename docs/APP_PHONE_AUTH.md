# App 手机号注册登录与地图移除

交付版本：**1.8.0-rc.4+33**；数据库：**Schema19**。仅本机配套服务升级，不部署生产，不更新正式下载入口。

## 功能与页面

- App 首页、厂家列表及原生地图实现、轮廓读取与统计请求已移除。首次启动清理旧 `verified-boundaries` 缓存；地区筛选及企业地区选择保留。网页登录注册及网页地图保留。
- 厂商与访客使用独立入口、同一个手机号表单。登录为手机号＋密码；注册为手机号、短信验证码、设置密码、确认密码。验证码与发送按钮同行，无身份或短信登录方式切换。
- 页面采用浅灰背景、蓝白单卡片、外侧16px、卡片20px、表单最大440px。控件至少48px，支持滚动和错误定位。密码仅在输入控制器中存在，不存草稿或本机设置；禁用密码自动填充提示，成功登录或切换模式后清空。
- 厂商账号从访客入口登录可同步收藏，不强制进入厂商工作台。访客在厂商入口验证密码后，先确认升级，再用同一账号继续企业资料与审核流程；升级不会创建或公开展厅。
- 旧用户名登录入口、登录帮助和旧短信账号设置密码入口保留。旧账号登录后可跳过手机号绑定；账号设置中可继续绑定。只有已验证手机号的访客能升级厂商。
- 新账号内部用户名使用随机稳定标识；App 优先显示手机号。后台沿用现有列表与重置布局，支持手机号查询和厂商／访客手机号账号密码重置。

## 接口

前缀 `/api/v1`，JSON 请求。需要认证的请求使用现有 `Authorization: Bearer` 会话。详细结构见 `openapi.json`。

| 方法与路径 | 请求字段 | 行为 |
|---|---|---|
| POST /auth/phone/code | phone, purpose=register / setup_password | 发送对应用途验证码 |
| POST /auth/phone/register | phone, code, password, role=merchant / visitor | 201，创建账号和会话；无展厅 |
| POST /auth/phone/password | phone, password | 200，返回实际身份与会话 |
| POST /auth/phone/password/setup | phone, code, password | 仅原短信且无密码账号；保留账号，撤销旧会话 |
| POST /auth/me/phone/code | phone | 已登录账号申请绑定，验证码绑定账号ID |
| PUT /auth/me/phone | phone, code | 首次绑定；保留密码及原用户名，撤销旧会话 |
| POST /auth/me/merchant-upgrade | confirmed=true | 已验证访客明确升级，保留账号ID和收藏，撤销旧会话 |

会话中的 `account` 增加 `phone`（可空）、`phone_verified`、`requires_phone_binding`。`GET /public/config` 中 `capabilities.phone_password_auth=true` 标识该功能；App 遇到未升级服务会给出明确提示，不调用新认证写接口。

手机号沿用中国大陆11位规则；密码为12–72个UTF-8字节，保留空格，不能全空白。确认密码仅客户端校验。短信沿用供应商适配器：6位、5分钟、60秒发送间隔、最多5次错误、一次性使用。新用途间及旧短信接口共用手机号发送冷却；注册、设置密码、绑定用途隔离，绑定额外限定账号ID。验证码存加盐摘要；仅开发环境与开发短信供应商同时启用才在响应中返回开发验证码。

发送接口另有IP每小时20次、号码每小时10次限制；注册类每IP每分钟10次、手机号密码登录每IP每分钟10次且每号码每分钟20次。错误包括 `invalid_phone`、`invalid_code`、`phone_exists`、`phone_already_bound`、`password_setup_unavailable`、`phone_binding_required`、`confirmation_required`、`rate_limited`、`sms_disabled`、`sms_unavailable`。

注册响应丢失时页面禁止重复提交，提示使用刚才的手机号和密码登录。手机号冲突由管理员核对，不自动合并、接管或重新归属资料。已有密码账号不能通过旧短信设置密码流程重置密码。忘记密码沿用后台重置。

旧 `/auth/merchant`、`/auth/visitor`、旧注册和 `/auth/sms`、`/auth/phone` 接口保留；角色限定的原用户名密码接口同时支持已验证的手机号。新旧流程对手机号身份冲突使用同一行锁串行化。账号响应不返回密码哈希；操作记录使用脱敏手机号。

## Schema19与恢复

`server/migrations/019_phone_accounts.sql` 增量新增：

- `accounts.phone`（可空唯一）、`accounts.phone_verified_at`；不自动回填企业展示联系电话或旧数字用户名。
- `phone_verifications`：手机号＋用途＋账号ID联合主键，含摘要、随机盐、过期与发送时间、错误次数及消费状态。
- `phone_identity_locks`：统一协调新旧手机号身份分配。

保留既有账号ID、用户名、密码哈希、会话和内容归属；不改写历史分类、审核快照、媒体或企业资料。MySQL DDL中断后按已有列／索引重试，重复迁移保留数据。

完整备份自动包含新增表，恢复支持最高Schema19。恢复激活时撤销会话和两类验证码，已验证手机号、密码哈希与内容继续保留。隔离库测试覆盖迁移重跑、故障回滚和备份恢复。

1. 本机升级前停止服务，备份完整SQL、媒体、旧可执行文件、网页文件和本机配置，记录业务数量及审核快照哈希。
2. 替换配套服务并启动，自动执行Schema19；核对健康、能力标识、业务数量和审核快照哈希，再检查网页地图与旧登录页面。
3. 本机网页：`http://localhost:8080`。手机与电脑同网络时，在App“我的 → 设置 → 服务地址”填电脑可达地址，如 `http://172.27.35.2:8080`。APK继续沿用原默认服务地址；已有保存的地址保留。生产服务未升级时显示升级提示。
4. 本机开发短信供应商可返回开发验证码用于验证流程；真实短信发送依赖既有供应商配置，本次不修改短信凭据、不向真实用户发测试短信。
5. 回退先停止服务并另做最新完整备份，保留Schema19表和新字段，使用能保留手机号字段、用途验证码及新身份规则的兼容后端。不可直接用旧库全量覆盖新增账号、手机号和升级数据。需要恢复备份时使用现有隔离恢复与预检流程，核实备份时间后的数据处置。

部署包不含数据库、媒体、私密配置、签名密钥或本机轮廓预览资源。Linux可执行文件已构建，未在Linux主机运行；本次仅更新本地Windows服务。
