# 产品页页脚下方留白：布局加固与本机验收

用户反馈线上 `/products/23` 在360浏览器中偶尔出现页脚下方大面积空白，刷新后恢复。本次只修改本机代码及18086预览，没有部署线上、重打安卓包或推送GitHub；保留此前抖音功能的未提交改动。

**检查结果与修复**

原公共正文的最低高度为 `calc(100svh - 72px)`，未计入实际页脚高度，也没有旧视口单位回退。页面高度由正文单独估算，加载中、内容很短及视口变化时没有整体的页头/正文/页脚高度分配。`svh`/`dvh` 从 Chrome 108 开始支持，旧内核会忽略不认识的声明，参见 [Chrome官方说明](https://developer.chrome.com/blog/chrome-108-beta)。

现在仅为 `/products/:id` 增加 `public-product-shell`：

- 整体使用纵向弹性布局，最低高度先使用 `100vh`，支持新单位时使用 `100dvh`。
- 页头、页脚保留自然高度，不压缩；正文使用剩余空间，产品内容较长时正常撑开页面。
- 产品页覆盖旧的固定减去72px规则；不设置固定页面高度，不裁切内容、不隐藏页面溢出、不用定时强制刷新或重置滚动。
- 公共页脚组件及样式、地图、注册登录的紧凑布局、厂商独立展厅布局均不修改。

这修正了产品页的高度分配和单位兼容问题；**不能据此认定已找到用户截图中偶发状态的唯一触发原因**。本机360支持 `svh`，常规原页面测试中没有稳定出现同样空白。360已有窗口的具体模式、插件及当时状态仍可能影响触发，本次没有改动个人浏览器配置。

**改动文件**

- `web/src/main.tsx`：引入样式，仅为产品详情页添加独立容器类。
- `web/src/product-page.css`：产品页专用高度布局，18行，无业务逻辑修改。
- `scripts/verify-product-footer.cjs`：本机只读浏览器回归脚本，检测页脚与文档底部差值、视口填充及横向溢出。

修改前的主文件保存在 `.local/footer-gap/main-before.tsx`。本次没有修改数据库、产品内容、媒体文件、后端接口或安卓代码。
