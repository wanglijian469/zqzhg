# 中企展馆www域名访问修复

2026年10月30日，正式入口保持`https://zqzhg.com`。

## 原因和修复

- 裸域名和www的DNS均已正确指向同一服务器。原Nginx没有匹配www，HTTP内部测试误进入同机另一站点；原证书只包含裸域名。
- 公网80端口原先超时，Nginx监听及主机防火墙正常。用户在阿里云控制台放行80端口后，两个域名的HTTP证书验证路径均返回200及正确内容。
- HTTP虚拟主机增加www，证书验证路径保持可读，其余请求301跳转主站；HTTPS增加独立www跳转，完整保留路径和查询参数。
- 现有证书扩展为同时覆盖`zqzhg.com`与`www.zqzhg.com`，复用原证书名称、webroot及续期任务。公开证书有效期至2027年1月28日。
- 备份Nginx、证书及续期配置后分两阶段平滑重载。私钥及具体备份位置仅在ECS及私有运维记录中维护，不随公开源码分发。

## 验证

- 三种入口、首页／地图／下载页／APK路径共12项301检查通过，查询参数保留；两个域名通过受信任TLS证书验证。
- 主站首页、登录页、地图页、厂商展厅正常；正式APK仍为1.10.5+43，下载按钮及二维码目标一致，未重新编译或替换APK内容。
- 同机官网正常，其他Nginx配置哈希保持；既有旧版后端位于独立回环端口，仍被旧域名引用，与Nginx的80端口不冲突，本轮保留该服务。
- 使用ACME测试环境对同一证书执行续期演练及部署钩子，两个域名均成功；原每日两次自动续期任务保持启用。
- 生产地图全国→河北→邢台→宁晋的完整几何数据与本机保存的开发映射快照逐项相同，统计11／10／8／8；五种屏幕尺寸、中英文、缩放筛选、展厅返回及资源失败重试通过。开发服务未启动，因此本轮明确选择已保存的开发缓存比对，并保留原130571缺少独立轮廓的限制。
- 继续使用现有已发布程序、数据库和地图资源；没有创建测试账号或发送真实短信。

公开检查记录：`docs/test-output/www-public-routing-20261030.json`及`www-renewal-20261030.json`。地图回归记录为`www-20261030-map.json`。

## 后续维护

Nginx最终模板为`deploy/linux/zqzhg-https.conf`，初次证书引导模板同时支持两个域名。操作工具`deploy/linux/configure-zqzhg-www.py`先启用HTTP挑战路径，证书覆盖两域名后才启用www的HTTPS入口；配置检查或本机跳转验证失败时恢复该阶段原配置。

公网TCP80应持续可达，供HTTP跳转及自动续期使用。证书更新使用现有webroot流程，不依赖DNS AccessKey。出现配置问题时在ECS恢复相应阶段备份并先执行`nginx -t`再平滑重载，保持已可用主站服务。
