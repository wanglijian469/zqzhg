# 后台运营与数据管理 V1.6.0

网站、Go API 和 Android `1.6.0+28` 配套升级。原厂商账号、审核版本、媒体 ID 与公开地址保留。新增的是平台操作员，不是厂商子账号。生产存储启用、历史迁移、备份策略启用及恢复切换，均由管理员在页面发起。

## 页面与权限

- `/admin/analytics`：PV、端内匿名 UV、访问次数、按日趋势、网站/Android 来源、厂商/产品/视频图册排行、搜索词、设备与来源站点、拨号和微信复制点击；按北京时间日期筛选，CSV 导出。
- `/admin/operators`：新建操作员、修改功能权限、启停、随机密码重置。密码仅返回一次；编辑、审核、下架自动包含对应查看。改权、停用、重置均删除旧会话。
- `/admin/storage`：本地目录和 OSS 配置、测试、默认位置、迁移、显式清理旧副本。
- `/admin/backups`：手动备份、定时策略、加密包下载/导入、校验、隔离恢复、重新验证管理员后切换、回退、任务进度。

操作员授权目录由 `/admin/permissions` 提供。后端每个管理接口按同一目录检查，前端按 `/auth/me` / 后台账号响应中的有效权限隐藏菜单和按钮；直接输入页面路径或构造请求也不能越权。操作员不能管理平台账号授权、厂商账号密码、存储密钥或备份恢复。私有媒体按资料关联和权限检查；操作员上传的未保存草稿通过上传审计范围预览，媒体仍归厂商所有。

## 统计口径与隐私

`page_view` 只在公开页面导航时上报；后台、厂商私有页面、轮询、资源下载不算 PV。网站 SPA 导航、Android 底部标签与公开详情均有采集。公开视频/图册打开记录 `resource_view`，拨号/复制微信记录点击，不解释为通话接通、加好友或成交。

匿名标识保存在各端第一方存储中，每个来源独立 HMAC；Android 按服务器地址隔离。访问会话闲置 30 分钟后更换。匿名 UV 是端内设备标识，不能当作真实人数；日期范围内直接去重，不累加每日 UV。事件 UUID 唯一键去重；队列上限 100、每批 20、最多尝试 3 次、滞留超过 24 小时丢弃。采集失败不阻塞业务。旧 App 继续使用原业务接口，升级后开始采集。

服务器不在事件表保存 IP、联系人数据、账号标识或完整来源 URL；来源只保留主机名。搜索词限制 80 个字符并脱敏电话、邮箱及凭据形态；客户端也会脱敏后再保存待发队列。明细默认保留 90 天，日报保留 24 个月，后台任务每分钟聚合和清理。停机后先补齐未聚合日期，再清理过期明细。含归档日期的查询只提供日报，跨日 UV/访问去重和排行显示不可用，不生成估算人数。

CSV 为 UTF-8 BOM，统一列为 `section,date,source,metric,name,id,value`，包含范围汇总、日报与当前可用排行；`daily_anonymous_uv` 明确为单日指标。文本单元格做公式注入防护。

## 服务器配置

参考 `server/.env.example`。升级前在服务器配置以下内容，并由服务账号持有私有目录权限：

| 配置 | 用途 |
| --- | --- |
| `OPERATIONS_DIR` | 持久化任务、活跃数据指针、迁移旧副本清单、备份目录与独立工作目录，必须在公开网站目录外。默认是 MEDIA_DIR 同级的 `.operations-目录名`。生产建议显式配置固定绝对路径。 |
| `CONFIG_ENCRYPTION_KEY` | 32 随机字节，64 位十六进制或标准 Base64。AES-GCM 加密 OSS 凭据与备份。生产缺失时相应功能拒绝执行。开发模式自动生成控制目录中的 development.key。 |
| `MYSQL_BIN` | MySQL 8 的 mysql、mysqldump 目录；不配置则查 PATH。 |
| `DB_MAINTENANCE_USER/PASSWORD` | 仅服务器保存的恢复维护账号；需能新建 `zqzt_exhibition_restore_*` 库、建立/删除临时导入用户、仅为目标库授权，并为应用账号授予新库权限。生产缺失时恢复拒绝执行。 |
| `MAX_BACKUP_GIB` | 导入及展开上限，默认 20 GiB；需为加密包、ZIP、展开资源和数据库留足空间。 |

主密钥与服务器数据库凭据不写进备份。应单独安全保管主密钥、服务器配置及控制目录；丢失主密钥将无法读取旧凭据与加密备份，不能直接换一个新值继续使用。控制目录中的 `analytics.key` 也需单独保存，以保持原匿名统计连续性。Android 发布签名仍沿用 `.local/signing` 的原密钥，不能替换。

Linux 服务账号要能写 MEDIA_DIR、OPERATIONS_DIR、配置的本地资源/备份目录；本地对象采用完整写入、同步后以硬链接原子发布，目录所在文件系统需支持硬链接（已测 NTFS；Linux 建议 ext4/XFS）。不要将私有目录通过 Nginx 静态公开。备份和媒体经 API 鉴权代理读取。

MySQL SQL 导入使用随机临时用户，只被授予新恢复库权限，结束后删除；禁用 LOCAL INFILE，非交互 binary-mode 禁止执行客户端文件命令。应用账号不需要拥有全局恢复权限。维护账号权限应由数据库管理员按实际 MySQL 环境配置并验证，不在网页输入或返回。

## OSS 与历史资源

使用[阿里云 OSS 官方 Go SDK V2](https://www.alibabacloud.com/help/en/oss/developer-reference/manual-for-go-sdk-v2/)。测试与启用会检查 Bucket ACL 为 private，并实际完成写入、读回 SHA-256 与删除探测对象。RAM 身份需有目标 Bucket 的 GetBucketAcl 及目标前缀的 GetObject、PutObject、DeleteObject 权限。Endpoint 可留空由 Region 推导，或使用无路径、无查询参数的阿里云 HTTPS Endpoint。

媒体与备份目标分别配置。OSS 对象强制 private，禁止覆盖；后端按现有媒体发布条件鉴权，再代理 Range/HEAD 读取，不向客户端暴露签名 URL。原图、缩略图、封面、PDF、图册、视频源及转码文件、首页图均进入逐对象位置记录。转码/PDF 处理在控制目录的工作目录进行，产物写入当前默认存储。

切换默认位置只影响新上传。迁移扫描后逐对象复制、核对字节数和 SHA-256，只有校验通过才改变该对象的位置记录。中断后任务标为 interrupted，可在页面重试，已迁移对象跳过；旧副本保留。迁移、备份、恢复任务串行，清理操作在任务进行时拒绝执行。清理只处理当前数据库中已无位置引用、校验仍匹配的迁移旧副本；未迁移资源不会被删。仍有资源、默认配置、备份引用的存储配置不能删除。

## 备份、恢复与回退

定时模板为北京时间每日 02:00、保留最近 7 份，默认关闭，管理员选好目标并启用后生效。服务恢复运行后会补发当日错过的定时备份。手动/导入备份不参加定时清理。每份备份包含数据库 SQL、平台配置、所有已登记和原有目录中的媒体对象、处理中视频源，以及版本/表行数/对象字节数/SHA-256 清单；OSS 对象的实际字节会复制到包内。

建立清单和 SQL 快照时拒绝新的业务写请求并等待已有写入、转码排空；公开查询继续可用。复制媒体和加密阶段恢复业务写入。对象不可覆盖，任务完成前清理受保护。备份采用分块认证加密，完整性检查拒绝错误密钥、截断、追加数据或篡改。

下载使用 HttpOnly、SameSite=Strict、两分钟有效且绑定当前管理员会话的凭证，浏览器直接流式下载，不将大包读入页面内存；退出或切库撤销会话后凭证也失效。导入专用接口每块 8 MiB，校验顺序和偏移，绕开普通 JSON 1 MiB 限制。失败分块可重试相同未提交偏移；刷新页面后可重新导入，未完成上传元数据保留 24 小时有效。反向代理需为 `/api/v1/admin/backups/imports/` 及 `/api/v1/backup-download/` 放宽请求体/流传输超时，关闭下载缓冲并避免缓存授权响应。程序为备份下载单独延长写超时至 24 小时。

固定流程：选择/导入 → 完整性检查 → 隔离恢复 → 检查结果 → 输入当前管理员密码（目标账号不同则同时填写目标凭据）→ 确认切换。预检验证格式/版本、密钥、展开路径、空间、SQL 目标库权限、表行数和可用管理员；新库和资源目录使用独立名称。恢复不会就地覆盖业务库。

切换将进入维护，排空请求，暂停后台任务，先持久化 pending 指针，再切换连接与资源配置；健康检查失败恢复原配置。成功后清除全部会话，重新登录。旧库、资源和记录保留，可以从页面重新验证管理员身份并回退。进程重启发现 pending 会恢复旧指针；已确认指针继续使用新库。维护期间短期令牌只能查询对应任务进度。不要删除旧库和控制目录，或同时启动两个实例写同一控制目录。

## 升级与验收

迁移 `010_operations.sql` 只新增表，CREATE IF NOT EXISTS 可在中断后重新执行；原迁移记录、内容和媒体保持兼容。先在独立 MySQL 库与目录运行验收，再替换生产程序与网站；不要把测试库、development.key、测试凭据或数据包带到生产。旧服务进程与新服务不能同时管理同一数据。

构建和验证命令：

```powershell
. ./scripts/go-env.ps1
cd server
$env:RUN_MYSQL_TESTS='1'
go test -timeout 300s ./...
go vet ./...
cd ..
& D:/nvm4w/nodejs/npm.cmd --prefix web test
& D:/nvm4w/nodejs/npm.cmd --prefix web run build
. ./scripts/flutter-env.ps1
cd mobile
& $taskFlutter analyze --no-pub
& $taskFlutter test --no-pub --timeout 90s
cd ..
./scripts/build-apk.ps1
```

完整浏览器演练使用 `TestOperationsBrowserFixture` 显式创建的隔离库和本机 `18096` 端口，执行 `node scripts/verify-operations-v16.cjs`，报告见 `docs/test-output/operations-v16-browser.json`。该脚本会在测试库进行真实切换和回退，禁止对生产地址运行。

真实 OSS 联调需另外提供隔离 private Bucket，在服务器环境设置 `RUN_MYSQL_TESTS=1`、`RUN_OSS_TESTS=1`、`OSS_TEST_REGION`、`OSS_TEST_BUCKET`、`OSS_TEST_ACCESS_KEY_ID`、`OSS_TEST_ACCESS_KEY_SECRET`（可选 `OSS_TEST_ENDPOINT`），运行 `go test -run TestRealOSSPrivateStorage -v`。密钥不写进命令行或测试报告。本次未提供隔离 Bucket，真实云端的混合读取、视频/PDF、迁移和完整恢复联调仍需完成，不能以模拟协议测试替代云端验收。
## Linux 交付包安装

交付目录 `delivery/operations-1.6.0/` 包含两个 Linux 架构的后端、网站和原签名 APK、迁移 010、示例配置、说明与 SHA256SUMS。`upgrade-v16.sh` 对已有 `/opt/zqzt` 托管安装执行程序升级：核对哈希、保留旧版本、停止服务、原子替换 current、健康检查失败自动回到旧程序；不启用存储、不迁移生产媒体、不恢复业务库。配置沿用 `/etc/zqzt/exhibition.env`（可用 ENV_FILE 指定），不能用示例覆盖现有文件。

管理员先完成数据库/媒体的独立升级前备份，按前述配置固定控制目录和主密钥，再在解压后的交付目录执行 `sudo bash upgrade-v16.sh`。需要恢复能力时单独配置维护数据库账号。首次安装仍按现有 `deploy/linux/README.md` 流程准备应用账号与服务，随后使用本版本程序。切换数据库前应结束长时间的媒体或备份下载，维护闸门会等待在途请求完成。
