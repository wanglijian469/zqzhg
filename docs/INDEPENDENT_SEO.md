# 厂商展厅与产品独立 SEO

每家厂商展厅和公开产品详情均提供独立地址、服务端正文、标题摘要和结构化数据。默认中文收录，保留原有英文界面切换，不增加英文独立网址、后台 SEO 编辑项或数据库迁移。

## 地址与页面内容

| 地址 | 用途 |
| --- | --- |
| `/v/{slug}` | 厂商展厅；未设置品牌标识时使用 `/v/v-{id}` |
| `/products/{id}` | 独立产品详情 |
| `/sitemap.xml` | 厂商和产品站点地图索引 |
| `/sitemaps/vendors-1.xml` | 厂商地图分片，编号从 1 开始 |
| `/sitemaps/products-1.xml` | 产品地图分片，编号从 1 开始 |
| `/robots.txt` | 爬虫访问规则与完整 Sitemap 地址 |

展厅初始 HTML 包含企业名称、公开简介、主营业务、地区、地址、联系方式、图片和最多 8 款首页产品的普通链接，产品选择与现有展厅首页一致。全部公开产品通过站点地图发现。产品初始 HTML 包含名称、型号、品牌、介绍、参数、图片及所属厂商链接。缺失资料不编造，缺少封面或产品图时不输出相应图片元信息。

正文由 Go 模板安全转义后放在 `#root` 内。关闭 JavaScript 仍可阅读并点击企业与产品链接；开启 JavaScript 后 React 替换同一容器，保留现有手机和电脑展厅体验。普通访客与搜索爬虫收到相同初始内容，不提供 User-Agent 特殊版本。

标题、摘要、Open Graph 和 JSON-LD 使用审核通过的公开资料生成。企业使用 `Organization`，产品使用 `Product`，仅包含真实已有字段；未录入的价格、库存、评分和评论不补造。产品型号优先使用独立 `model` 字段，兼容从旧版参数文字提取。结构化数据不代表一定获得搜索引擎的商品富媒体展示资格。

## 规范地址与公开边界

- `/vendors/{id}`、已登记历史品牌地址，以及设置品牌地址后的 `/v/v-{id}`，均以 301 跳转到当前 `/v/{slug}`，保留查询参数。
- 展厅所有栏目、语言、筛选和分页的 canonical 均为展厅主地址。关键词、分类等筛选及第 2 页起设为 `noindex,follow`；普通栏目仍可跟随链接。
- 产品 canonical 去除查询参数，前后端保持一致。界面切换仍保留用户的搜索与返回状态。
- 复审期间使用旧公开版本；草稿和待审修改不进入正文或结构化数据。筹建展馆、未公开及下架内容不进入地图。厂商下架后，其产品同步退出公开页面和地图。
- 无效或未公开页面返回 `404` 和 `noindex`；数据库查询失败返回 `503` 和 `noindex`。不返回已缓存的旧正文。
- 站点地图实时查询，每片最多 1,000 条，按内容 ID 稳定排序，不缓存；不存在或已为空的分片返回 404。未使用编辑草稿的时间充当公开更新日期，因此暂不输出 `lastmod`。
- `robots.txt` 保留 `/admin`、`/merchant`、私有 API 和既有指定爬虫限制，允许 `/api/v1/public/` 和 `/api/v1/media/`，以便搜索引擎渲染页面及获取公开图片。媒体的审核和权限检查保持生效；普通页面和站点地图继续执行限流，不因自称搜索爬虫而豁免。

## 生产配置与提交收录

1. 后台“系统设置”的网站地址填写正式 HTTPS 域名；尚未保存网站地址时兼容 `PUBLIC_BASE_URL`。二者都填写时，以后台网站地址为准，避免索引内出现本机地址或错误域名。
2. 同时更新 Go 服务及 `web/dist`，沿用现有部署和备份流程，无需新增数据库迁移。反向代理需将展厅、产品、`/robots.txt`、`/sitemap.xml` 和 `/sitemaps/` 转发给 Go，不能直接把这些请求兜底为静态 `index.html`；CDN 不应缓存这些动态响应。
3. 检查正式域名下 `/robots.txt` 中的 Sitemap 地址及地图内的企业、产品地址；匿名打开任一地址，检查状态码、规范地址和页面源代码正文。确认公开图片可访问。
4. 使用网站所有者账号完成百度搜索资源平台、必应 Webmaster Tools、Google Search Console 的站点验证，并提交正式域名下的 `/sitemap.xml`。验证及账户操作由站点所有者完成，不在此次代码更新中自动登录或提交。
5. 后续在站长平台观察地图读取、抓取错误、已索引页面及重复规范地址；结合服务日志查看 404、503 和 429，按实际访问情况调整既有访问配额。

本次只在本机实施和验收，不部署生产或向生产写入测试数据。技术交付以页面可发现、可抓取和可索引为准，不保证实际收录时间或排名。

## 验证命令与证据

在项目根目录加载 `scripts/go-env.ps1` 后进入 `server`：

```powershell
$env:RUN_MYSQL_TESTS='1'
go test ./...
go vet ./...
```

MySQL 测试仅创建 `zqzt_exhibition_test_*` 隔离库，结束后自动清理，不使用业务库写入测试资料。

在 `web` 执行 `npm test -- --maxWorkers=2`、`npm run build`。本机默认启动 37 个测试进程时出现超时，限制为 2 个进程后完整通过。若本机未提供 npm 命令，可直接使用 Node 运行依赖中的 Vitest、TypeScript、Vite 入口；构建前仍执行 `package.json` 约定的三个预构建脚本。系统临时目录不可用时，将当前进程的 `TEMP`、`TMP` 指向项目内独立临时目录后重试。

构建后可在 `server` 进行真实浏览器验收：

```powershell
$env:RUN_MYSQL_TESTS='1'
$env:RUN_SEO_BROWSER='1'
go test -run '^TestIndependentSEOBrowser$' -v
```

该测试启动临时 HTTP 服务和隔离数据库，通过本机 Edge/Playwright 检查 390/1440 像素、中英文、禁用 JavaScript 的企业和产品正文及链接、React 挂载后的单份正文、手机页面溢出、产品往返导航、canonical 与分页 noindex。截图位于 `docs/screenshots/independent-seo/`，结果位于 `docs/test-output/seo-browser.json`。
